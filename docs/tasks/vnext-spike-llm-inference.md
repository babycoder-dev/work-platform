# 任务包：vNext spike —— 内网 LLM 推理基线评估（M15 部署前置）

状态：Ready（**前置**：`docs/adr/0006-vnext-roadmap.md` 与 `docs/research/README.md`
随文档落地计划 Task 1/6 入库后方可开工）｜ 类型：研究型 spike（产出报告 + 采购建议，
不改产品代码）｜ 依据 `docs/adr/0006-vnext-roadmap.md`（设计推演见
`docs/superpowers/specs/2026-07-05-vnext-roadmap-design.md` §2/§8.1/§14）；报告规范见
`docs/research/README.md`。

> **这是缺漏审计定级 P0 的 spike，也是唯一带 go/no-go 判定的 spike**：spec 拍板"内网自
> 部署 LLM 为缺省通道"，但硬件/模型/推理服务零落地规划。本 spike 结论若为"不可行"，须
> 按 spec §14 回到 §2 前提重议（云通道为主或缩小 M15 场景）——越早知道越好。

## 1. 目标

回答一句话：**"一台什么规格的内网服务器，跑什么开源模型，用什么推理服务，能支撑 M15
内置数字员工的真实工作负载？"**——产出分档采购建议与 go/no-go 判定，作为 M15 的部署
前置与 `docs/deployment.md` 容量规划输入。

## 2. 需求侧锚点（从 M15 场景反推，写死在报告开头）

- 负载形态：几百人企业、并发活跃会话预估 ≤ 20、单会话 agent loop 3-10 轮工具调用。
- 能力红线（按优先级，**每条给可判定数值**）：① **工具调用（function calling）可靠性**
  ——参数 JSON 合法率 **≥ 95%**（30 样本中 ≤ 1 次失败；落在 90-95% 边界区间则加测至 50
  样本再判），且 3-10 轮 agent loop 完整跑通 **≥ 9/10 次**；② 中文理解与生成质量（自测
  样本主观达标 + 公开中文基准分参考）；③ 上下文窗口 ≥ 32k（档案/表单上下文注入）；
  ④ 流式输出首 token **≤ 3s**（10 并发下）。
- 明确不追求：创作类长文生成、多模态（本期无场景）。

## 3. 范围

**做**：

1. **模型候选矩阵**：以 spike 执行时点的主流**开源权重**为准（如 Qwen、DeepSeek、GLM 等
   系列的当期版本），按参数量分档（~7B / ~14B / ~32B / 70B+），逐档记录：许可证（可否
   内网商用部署——我们虽不商业化，仍记录）、工具调用基准表现（公开基准 + 自测）、中文
   能力口碑与自测样本。**不臆测训练截止后的新模型，一律以执行时点实查为准。**
2. **推理服务对比**：vLLM（预倾向）/ SGLang / Ollama——OpenAI 兼容端点完整度（尤其
   tool-call 协议）、并发吞吐、量化格式支持（AWQ/GPTQ/GGUF）、离线安装难度、运维面
   （监控指标暴露）。选型建议一档 + 备选一档。
3. **硬件分档方案**（3 档，含大陆市场可采购性与约当价位）：
   - 入门档：单卡消费级（如 4090/5090 级 24-32GB）→ 能跑什么档模型（量化后）；
   - 标准档：单卡专业级（如 L20/A6000 级 48GB）；
   - 富裕档：双卡或 96GB 级。
   每档映射"可跑模型 × 量化 × 预估并发"，并给出**推荐档**。
4. **实测**（核心交付，不许纸上谈兵）：在可获得的硬件（本地或短租云 GPU 等效卡）上，
   对**推荐档模型 × 推荐推理服务**实测，且**分两个上下文档位**（短 prompt ~2k 与 ~32k
   填充——KV cache 显存在长上下文下直接改写并发上限，只测短 prompt 的并发数对档案/表单
   注入场景无参考价值）：tokens/s（单路/10 并发 × 两档上下文）、首 token 时延、**pi-ai
   经 OpenAI 兼容端点跑通 3 轮以上工具调用循环**（Agent 运行时 spike 可共享该环境；若本
   spike 环境在短租云上不可共享，Agent spike 可独立降级用本地 Ollama 端点完成其工具调用
   项，两包解耦）、工具调用参数合法率（按 §2 红线①采样规则）。§3.3 硬件映射表中每格
   "预估并发"须标注所依据的上下文长度假设。
5. **离线交付链路**：模型权重（数十 GB）+ GPU 驱动 + CUDA/容器运行时 + 推理服务镜像的
   air-gap 导入步骤清单（进 `docs/offline-deployment-runbook.md` 的素材）。
6. **go/no-go 判定**：判定对象是"可采购范围内**是否存在任何一档**能达到 §2 全部红线"
   ——**入门档失败但标准档达标 = go（采购结论指向标准档）**，不是 no-go；只有推荐档及
   以下所有可采购档位均无法达标（或成本明显不可接受）时 → 报告显式给出 no-go 及两条
   退路（云通道为主 + 数据类别限制收紧；或缩小 M15 场景到纯查询类），触发 spec §14
   "回到前提重议"。

**不做**：微调/蒸馏、多模态评估、GPU 集群方案（单机为界）、与云 API 的质量对齐评测
（云通道是显式开启项，不是本 spike 对象）。

## 4. 执行步骤

1. 桌面调研（1 天等效）：模型矩阵 + 推理服务对比 + 硬件档位表初稿。
2. 实测环境（1-2 天等效）：无本地 GPU 则短租云实例（选与推荐档同卡型），部署推荐组合。
3. 跑 §3.4 实测项，记录原始数字。
4. 报告 `docs/research/llm-inference-baseline.md`（README 七章规范 + 采购建议表 +
   go/no-go 章）。

## 6. 风险与时间盒

- 时间盒：**4 个工作日等效**（含云 GPU 短租等待）；超盒带现有实测收口。
- 云 GPU 短租涉及少量费用与数据面：实测**只用合成样本**，不带任何真实业务数据出内网。
- 模型/推理服务版本更迭快：报告所有结论带版本锚点与日期，M15 RFC 引用时若超过一个季度
  须做一次轻量刷新（报告里写明此保鲜期）。
