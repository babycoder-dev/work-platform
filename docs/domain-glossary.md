# 领域术语表

本文档定义跨平台基建和业务模块复用的核心术语。它不替代具体 RFC；当某个模块需要更细规则时，以该模块 RFC 为准。

## 1. 平台基础

| 术语 | 定义 |
| --- | --- |
| 企业 | 系统内的最高业务组织边界。首期按单企业部署设计，但数据结构保留 `enterprise_id`。 |
| 部门 | 企业内组织单元。部门可以有上下级关系。 |
| 员工 | 企业内部人员的业务身份，归属一个企业和部门。 |
| 内部账号 | 员工用于登录系统的账号凭据。账号与员工身份由 Platform Core 维护。 |
| 角色 | 权限点和数据范围的组合。用户通过角色获得权限。 |
| 权限点 | 形如 `<module>:<resource>:<action>` 的最小授权单元。 |
| 数据范围 | 当前用户能访问哪些员工或部门数据的约束，包括 `self`、`department`、`department_tree`、`company`、`custom`。 |
| 模块 manifest | 业务模块声明自身权限、菜单、API prefix 和 Web entry 的契约。 |
| 审计日志 | 对登录、平台写操作和关键业务写操作的可追踪记录。 |
| 领域事件 | 模块内业务事实发生后的事件，例如 `presence.status.changed`。M4-M6 只要求可追踪，不要求通知推送。 |

## 2. 在位管理

| 术语 | 定义 |
| --- | --- |
| 在位状态 | 员工在某个时间点的工作状态，例如在岗、出差、外出调研、外出、休假。 |
| 状态记录 | 员工在一个时间区间内的在位状态登记记录。 |
| 当前状态 | 对某个查询时间点生效的状态记录计算结果；没有生效记录时默认为 `working`。 |
| 在位看板 | 按数据范围展示员工当前状态的列表或看板视图。 |
| 状态登记 | 员工或有管理权限的人创建、取消或修正状态记录的操作。 |
| 状态冲突 | 同一员工存在重叠的未取消非在岗状态记录。M4 首期必须拒绝此类冲突。 |

## 3. 审批

| 术语 | 定义 |
| --- | --- |
| 审批实例 | 一次业务审批流程的运行实例，例如一次请假申请。 |
| 审批任务 | 分配给某个审批人的待处理节点。 |
| 审批动作 | 审批人执行的通过、驳回、转交等操作。 |

审批模块的详细语义在 M5 RFC 中定义。

## 4. 工作汇报

| 术语 | 定义 |
| --- | --- |
| 日报 | 员工按日提交的工作内容、问题和计划。 |
| 周报 | 员工按周提交的工作总结和计划。 |
| 汇总上报 | 按组织层级聚合下属日报或周报并向上级展示。 |

工作汇报模块的详细语义在 M6 RFC 中定义。
