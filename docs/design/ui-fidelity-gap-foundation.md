# UI 还原度差距清单 · 地基三屏（登录页 / 应用外壳 / 工作台首页）

状态：Draft ｜ 2026-06-17 ｜ 作为「UI 还原收口切片」任务包的依据

## 这份文档是什么

把**设计真源**（`docs/design/ui-handoff/design/`，来自 Claude Design 交接包，README 要求**像素级还原**）
与**现有实现**逐项对照，列出地基三屏的不一致，供收口切片照单整改。

- 设计真源：`docs/design/ui-handoff/design/企业工作台设计规范.html`（§02 登录页、§03 应用外壳+工作台首页）
  - `tokens.css`（设计 token 唯一真源，主色 `#3370FF` 飞书蓝、4px 间距基准）。
- 现有实现：`apps/workbench-shell/src/app/App.tsx`（`LoginView` / `AppShell` / `WorkbenchHome`）
  - `apps/workbench-shell/src/styles.css` + `packages/ui/src/styles/{tokens.css,components.css}`。

## ⚠️ 一个必须先讲清的还原边界（重要）

设计稿是一个**虚构的、数据填满的企业门户**——里面画了**本产品当前并不存在的功能**：
「应用管理 / 在用应用 48 个 / 应用清单表格 / 本月工单 236 / 文档资料 / 审批中心(已建)」等。
因此"像素级还原"必须**分两层**，否则会要求实现根本没有的后端：

- **L1 视觉系统 + 外壳 chrome + 真实存在的屏 → 严格像素级还原**（token、间距、圆角、阴影、
  组件态、登录页、侧栏/顶栏布局骨架、工作台首页的版式语法）。这是本切片的硬门禁。
- **L2 映射到未建功能的内容 → 仅作视觉参考**：用设计的**视觉语言**去渲染**真实有的数据**
  （如工作台首页用设计的 stat-card / card / table 样式，但卡片内容接真实的通知/在岗/待办，
  而不是硬塞"48 个应用""本月工单 236"这些没有数据源的虚构内容）。功能屏(组织成员/消息中心/
  审批)按各自里程碑落地时,照对应设计稿做 L1 还原。

> 也就是说:**组件库与外壳要像素级对齐设计;工作台首页要用设计的组件重新搭建版式,但内容接真实数据**。
> 收口切片不负责把"应用管理/工单"这些虚构功能做出来。

## 4. 结论与收口切片应做的事

- **骨架(侧栏 220px、token 已 port)对了,但品牌、图标体系、文案、组件态、工作台首页版式与内容**大面积偏离设计。
  登录页是"形似神不似"(emoji 图标/文案/默认态);工作台首页基本是**另一个页面**(薄占位 vs 富仪表盘版式)。
- **token 已 port 但 `components.css` 的组件样式(btn/input/card/tag/table/checkbox)需逐一对齐设计规范的"基础组件/业务组件"段**——这是所有屏复用的根,优先做。

**「UI 还原收口切片」(M8 之前)范围据此固定:**

1. 设计真源**早已在仓库**(`docs/design/ui-handoff/`,含 294 行 README 把 6 屏列全)——本切片**不是补真源,而是补"照它实现+门禁"**。
2. **组件库对齐**:`packages/ui` 的 btn/input/card/tag/table/checkbox/avatar/badge 等照设计规范"基础/业务组件"段像素级还原(L1)。
3. **登录页**像素级还原(L-1..L-8)。
4. **应用外壳**还原(S-1..S-8),侧栏分组样式/面包屑/搜索/图标集对齐;分组内容仍随 manifest。
5. **工作台首页**用设计组件重新搭建版式(W-1..W-6),**内容接真实数据**,虚构功能位按 L2 处理。
6. **立"设计还原度"门禁**:每屏一张核对表(逐项 design-value vs impl)+ 截图比对,纳入交付验收。
7. 功能屏(组织成员→M8、消息中心→M7 回补、我的待办/审批→M11)在各自里程碑照对应设计稿做 L1 还原,不在本切片。

> 下一步:据本清单起草收口切片任务包(逐屏断言 + L1/L2 边界 + 门禁),独立 sub-agent 二审后交 Codex 实现。
